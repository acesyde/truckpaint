TruckPaint runs on Windows, macOS and Linux. You download it from GitHub, unpack it and run it. There is no installer.

## Download TruckPaint

1. Open the [releases page](https://github.com/acesyde/truckpaint/releases). The [latest release](https://github.com/acesyde/truckpaint/releases/latest) link goes straight to the newest one.
2. Download the file for your system. The version is part of the name:

   | System | File |
   |---|---|
   | Windows | `truckpaint-v<version>-windows-x86_64.zip` |
   | macOS | `truckpaint-v<version>-macos-arm64.zip` |
   | Linux | `truckpaint-v<version>-linux-x86_64.tar.gz` |

   The macOS download is for Apple silicon Macs only (M1 and later). There is no download for Intel Macs.

3. Unpack the archive. It holds one folder with the program (`truckpaint`, or `truckpaint.exe` on Windows) and the `LICENSE`.
4. Put the folder anywhere you like and run the program. You can also make a shortcut to it.

### The first launch

The programs are not signed, so your system may warn you the first time. This is expected. To see where a file was built, read [Check your download](#check-your-download). It does not remove these warnings.

- **Windows:** SmartScreen may show "Windows protected your PC". Click **More info**, then **Run anyway**.
- **macOS:** Gatekeeper blocks the first launch. The dependable fix is to remove the quarantine mark. In a terminal, run this with the path of the unpacked folder, then start the program:

  ```sh
  xattr -dr com.apple.quarantine <the unpacked folder>
  ./truckpaint
  ```

  On recent macOS, you can also open System Settings, go to Privacy & Security and choose "Open Anyway".
- **Linux:** nothing to do. Unpack and run:

  ```sh
  tar -xzf truckpaint-v<version>-linux-x86_64.tar.gz
  ./truckpaint
  ```

  The app needs the windowing and graphics libraries listed in [the prerequisites below](#install-the-prerequisites) when it runs. Most desktop systems already have them.

### Check your download

Each release has a `SHA256SUMS` file. It lists the checksum of every download. Compute the SHA-256 of your file and compare it with its line in that file:

```sh
sha256sum <file>        # Linux
shasum -a 256 <file>    # macOS
Get-FileHash <file>     # Windows, in PowerShell
```

You can also check where a file was built. This is optional. It needs the [GitHub CLI](https://cli.github.com) (`gh`) and an internet connection. Every release has an attestation for each download and for `SHA256SUMS`. Run this next to the file you downloaded, with its own name:

```sh
gh attestation verify truckpaint-v<version>-macos-arm64.zip -R acesyde/truckpaint
```

If the check succeeds, the file was built by TruckPaint's own release workflow, from a given commit, and it was not changed afterwards. If it fails, do not run the file, and report it on the [issues page](https://github.com/acesyde/truckpaint/issues).

:::note
An attestation is not a code signature. It shows where the file was built. It does not mean that Windows or macOS trust it. The programs are still not signed by Windows or Apple, so you still see the warnings in [The first launch](#the-first-launch).
:::

A published release never changes. Its files cannot be replaced or removed, so the file you download today is the same tomorrow.

### Pre-releases

A version with a suffix, such as `0.2.0-beta.1`, is a test build. The releases page marks it "Pre-release". Use it to try new things, and expect problems. The "latest release" link never points to a pre-release.

### Which version do you have?

Open <Ui id="cmd-about-truckpaint" />. On macOS it is in the TruckPaint menu. On Windows and Linux it is in the <Ui id="menu-help" /> menu. A build made from source shows "dev".

### Update to a newer version

Download the new release and replace the folder. Your preferences, your installed vehicles and your projects are kept: they don't live in the program folder.

## Build it from source instead

If you prefer, you can build the app yourself. It takes a few commands.

### Install the prerequisites

You need [Git](https://git-scm.com) to get the source code and [mise](https://mise.jdx.dev), which installs the right version of Rust and runs the build for you. Then add what your system needs to build a desktop app:

- **Windows:** the MSVC toolchain, from Visual Studio Build Tools with the C++ workload.
- **macOS:** the Xcode Command Line Tools. Run `xcode-select --install` in a terminal.
- **Linux:** the windowing and graphics libraries. On Debian or Ubuntu:

  ```sh
  sudo apt-get install libxkbcommon-dev libwayland-dev libx11-dev libxcursor-dev \
    libxrandr-dev libxi-dev libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev \
    libgl1-mesa-dev
  ```

  Both X11 and Wayland sessions are supported.

### Build TruckPaint

1. Get the source code:

   ```sh
   git clone https://github.com/acesyde/truckpaint.git
   cd truckpaint
   ```

2. Install the toolchain the project pins (Rust and its tools):

   ```sh
   mise install
   ```

3. Build the app in release mode:

   ```sh
   mise run build
   ```

   The first build downloads and compiles every dependency, so it takes a while. Later builds are much faster.

4. Start it. The executable is `truckpaint` (`truckpaint.exe` on Windows), in the `target/release/` folder:

   ```sh
   ./target/release/truckpaint
   ```

You can copy the executable anywhere you like, or make a shortcut to it.

To update a source build, run `git pull` in the project folder, then `mise install` and `mise run build` again. Your data is kept here too.

## If the app doesn't start

TruckPaint draws its window with Vulkan, DirectX 12 or Metal. With old graphics drivers or in a virtual machine, it can stop at launch with a graphics adapter error. Force another graphics backend with the `WGPU_BACKEND` variable:

```sh
WGPU_BACKEND=gl ./truckpaint      # OpenGL (Linux, Windows)
WGPU_BACKEND=vulkan ./truckpaint  # Vulkan
```

On Windows, in PowerShell, set the variable first: `$env:WGPU_BACKEND="gl"`, then run `.\truckpaint.exe`. If you built from source, the program is in the `target/release/` folder.

On Windows and Linux, if the window can't be moved or resized properly, open <Ui id="home-preferences" /> and check <Ui id="prefs-system-title-bar" />: the window then uses your system's frame, with the menus in a row below it.

TruckPaint writes a log of what it does, to the terminal and to a daily file in its data folder (`logs/`). Attach it when you report a problem.
