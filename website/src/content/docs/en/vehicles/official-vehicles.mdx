Official ETS2 trucks and trailers come as `.tpv` packages that you generate yourself from your installed game, as described below, and install by hand. <Ui id="home-new-project" /> and <Ui id="cmd-add-vehicle" /> list only installed vehicles. A package contains its templates and game data: after generation, installation, project creation and mod export need no game installation.

## Generate packages

Package authors can use the Rust `tpv` command, which reads the game's own archives and needs no other program:

```sh
mise exec -- cargo run --release -p tp-pack --bin tpv -- extract "/path/to/ETS2" \
  --package-version 2.0.0
```

Replace the path with your ETS2 installation. Supply an explicit SemVer package version. Add `--vehicle man.tgx_2020` or `--vehicle krone.coolliner` to process one truck or trailer; omit it for every discovered vehicle. `--output <directory>` changes the parent directory of the batches. When you publish a new batch, add `--previous <batch directory>` with the last published batch: a template that did not change keeps its layout version, and a changed one gets the next version, so the app warns players who update their projects.

The tool discovers official ETS2 trucks and owned trailers, including installed vehicle, trailer and tuning DLC. User mods and ATS are excluded. Each truck package contains all supported cabins and painted accessories. Truck and cabin names are the game's English names. Cabin templates are 4096 × 4096; accessory dimensions come from the game's paint definitions. Main templates superpose compatible painted options.

A trailer package has one main texture, 4096 × 4096, for every painted body, chassis and part that the game does not paint from its own region, and accessory textures shared by the whole trailer. When the game paints every part from its own region, the main texture is only 64 × 64 and carries the base colour. Bodies or parts that the game paints from the same region in every paint job share one texture (for example the 13.6 m dry van, insulated and reefer bodies of the SCS box trailer), so you paint them once. Trailers have no variants. SCS's own trailers have no brand in the game: they are named "SCS" followed by their game name, such as "SCS Box" or "SCS Silo". Trailers whose paint jobs only set a plain colour, such as the SCS flatbed, have no livery to paint: the report lists them as skipped, without a package.

Each run writes a unique subdirectory under `dist/` by default, holding valid packages and `report.json`. Intermediates are kept under `target/` only when a vehicle fails. A game file of a version the tool does not know stops with a message that names the file and the version. Incomplete or ambiguous vehicles, unsupported shaders and unsupported UV mappings are refused. Other vehicles continue; any failure makes the command exit unsuccessfully. No partial vehicle package is published.

The report records sources, versions, texture coverage, successes, failures and limits. Technical package validation does not prove correctness in game: new vehicles and new configurations still need game checks.

`missing_dependencies` lists missing references and their source definitions when available. `expected_dlc: null` with `dlc_origin: "unknown"` means the required DLC cannot be identified; the archive mentioning a reference does not establish which DLC supplies it.

Paint overrides pointing to accessories with no installed definition are excluded and reported with `disposition: "ignored_reference"`; they do not prevent package generation. Defined accessories whose selected model has no paint-job material cannot show a livery: they get no template and are reported with `disposition: "excluded"`. Required missing files and painted geometry that cannot be read still block extraction (`disposition: "blocking"`).

Supported paint shaders are `truckpaint`, `truckpaint.tsnmap` and `truckpaint.tsnmapuv`, with optional `airbrush`, `flipflake` and `altuv` flavors and `.a` or `.asafew.a` alpha-test suffixes. Templates trace the mesh UVs; they do not reproduce per-pixel opacity masks. Every template uses the ordinary paint UV layout, the one used by the game's colour paint jobs and by community templates, even on trucks whose materials also have an alternate layout. Missing or ambiguous UV mappings are refused. Materials tinted only by the base paint color do not establish a paint-job UV mapping; an accessory that only has such materials is excluded, as described above.

Finite UV coordinates outside [0, 1] are preserved, without wrapping, clamping or switching channels. The SVG viewport limits the visible wireframe to the texture. The report records `uv_bounds` and `out_of_bounds_vertices`; these surfaces need particular attention in game. Non-finite or unrepresentable coordinates remain invalid.

`dimension_diagnostics` lists every accessory with missing or conflicting crop dimensions, the candidate sizes, masks and referencing definitions/archives. When the game declares several sizes for one accessory, the largest is used (`disposition: "resolved_largest"`): paint UVs fit any size. For the same reason, a size smaller than 64 pixels on a side is scaled up (`disposition: "raised_to_minimum"`). An accessory that the game only covers with shared fill masks gets no separate texture and stays on the main texture (`disposition: "main_texture"`), as in the game's paint jobs that do not override it. The extractor never invents a size.

Generated packages carry a license ("Personal modding only, not for sale. Game content belongs to SCS Software."), and name SCS Software among their authors.

## Install and paint

1. Open the [Vehicle Library](../library/): use <Ui id="vehicles-install" /> to choose a `.tpv` you generated.
2. In <Ui id="home-new-project" />, check that installed vehicle, choose cabins and accessories, then use <Ui id="new-project-create" />.
3. Paint and save the project, then follow [Mod export](../../export/mod/).

<Shot name="vehicles/library" alt="The Vehicle Library with installed packages and the Install button" />

Keep packages for future installation. The game is needed only for generation. Custom vehicles and sample packages remain available.

## Retired packages

The Carsmaniac catalog and template pack workflow have been removed. Generated packages keep `official.ets2.<vehicle>`, including `official.ets2.daf.2021`. Remove old test packages manually before installing the generated replacements. There is no migration of old placements. Installing the same id and version replaces that installed version; another version is kept alongside it. Existing project files are not automatically rewritten.
