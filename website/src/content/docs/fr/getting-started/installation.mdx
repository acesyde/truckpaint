TruckPaint fonctionne sous Windows, macOS et Linux. Vous le téléchargez depuis GitHub, vous le décompressez et vous le lancez. Il n’y a pas d’installateur.

## Télécharger TruckPaint

1. Ouvrez la [page des versions](https://github.com/acesyde/truckpaint/releases). Le lien [dernière version](https://github.com/acesyde/truckpaint/releases/latest) mène directement à la plus récente.
2. Téléchargez le fichier correspondant à votre système. La version fait partie du nom :

   | Système | Fichier |
   |---|---|
   | Windows | `truckpaint-v<version>-windows-x86_64.zip` |
   | macOS | `truckpaint-v<version>-macos-arm64.zip` |
   | Linux | `truckpaint-v<version>-linux-x86_64.tar.gz` |

   Le téléchargement macOS ne convient qu’aux Mac Apple silicon (M1 et suivants). Il n’y a pas de téléchargement pour les Mac Intel.

3. Décompressez l’archive. Elle contient un dossier avec le programme (`truckpaint`, ou `truckpaint.exe` sous Windows) et le fichier `LICENSE`.
4. Placez le dossier où vous voulez et lancez le programme. Vous pouvez aussi lui créer un raccourci.

Il n’y a pas de bundle `.app` ni d’icône pour le moment.

### Le premier lancement

Les programmes ne sont pas signés : votre système peut donc vous avertir la première fois. C’est normal. Pour savoir où un fichier a été compilé, lisez [Vérifier votre téléchargement](#vérifier-votre-téléchargement). Cela ne fait pas disparaître ces avertissements.

- **Windows :** SmartScreen peut afficher « Windows a protégé votre ordinateur ». Cliquez sur **Informations complémentaires**, puis sur **Exécuter quand même**.
- **macOS :** Gatekeeper bloque le premier lancement. La solution la plus fiable est de retirer la marque de quarantaine. Dans un terminal, lancez ceci avec le chemin du dossier décompressé, puis démarrez le programme :

  ```sh
  xattr -dr com.apple.quarantine <the unpacked folder>
  ./truckpaint
  ```

  Sous un macOS récent, vous pouvez aussi ouvrir Réglages Système, aller dans Confidentialité et sécurité et choisir « Ouvrir quand même ».
- **Linux :** rien à faire. Décompressez et lancez :

  ```sh
  tar -xzf truckpaint-v<version>-linux-x86_64.tar.gz
  ./truckpaint
  ```

  L’application a besoin, à l’exécution, des bibliothèques de fenêtrage et graphiques indiquées dans [les prérequis plus bas](#installer-les-prérequis). La plupart des systèmes de bureau les ont déjà.

### Vérifier votre téléchargement

Chaque version contient un fichier `SHA256SUMS`. Il liste la somme de contrôle de chaque téléchargement. Calculez le SHA-256 de votre fichier et comparez-le à sa ligne dans ce fichier :

```sh
sha256sum <file>        # Linux
shasum -a 256 <file>    # macOS
Get-FileHash <file>     # Windows, in PowerShell
```

Vous pouvez aussi vérifier où un fichier a été compilé. C’est facultatif. Il faut le [GitHub CLI](https://cli.github.com) (`gh`) et une connexion à internet. Chaque version contient une attestation pour chaque téléchargement et pour `SHA256SUMS`. Lancez ceci à côté du fichier téléchargé, avec son propre nom :

```sh
gh attestation verify truckpaint-v<version>-macos-arm64.zip -R acesyde/truckpaint
```

Si la vérification réussit, le fichier a été compilé par le propre workflow de publication de TruckPaint, à partir d’un commit donné, et il n’a pas été modifié depuis. Si elle échoue, n’exécutez pas le fichier et signalez-le sur la [page des tickets](https://github.com/acesyde/truckpaint/issues).

:::note
Une attestation n’est pas une signature de code. Elle montre où le fichier a été compilé. Elle ne signifie pas que Windows ou macOS lui font confiance. Les programmes ne sont toujours pas signés par Windows ni par Apple : vous voyez donc toujours les avertissements décrits dans [Le premier lancement](#le-premier-lancement).
:::

Une version publiée ne change jamais. Ses fichiers ne peuvent être ni remplacés ni supprimés : le fichier que vous téléchargez aujourd’hui est donc le même demain.

### Préversions

Une version avec un suffixe, comme `0.2.0-beta.1`, est une version de test. La page des versions l’indique par « Pre-release » (préversion). Utilisez-la pour essayer les nouveautés, et attendez-vous à des problèmes. Le lien « dernière version » ne mène jamais à une préversion.

### Quelle version avez-vous ?

Ouvrez <Ui id="cmd-about-truckpaint" />. Sous macOS, il se trouve dans le menu TruckPaint. Sous Windows et Linux, il se trouve dans le menu <Ui id="menu-help" />. Une version compilée à partir du code source affiche « dev ».

### Passer à une version plus récente

Téléchargez la nouvelle version et remplacez le dossier. Vos préférences, vos véhicules installés et vos projets sont conservés : ils ne se trouvent pas dans le dossier du programme.

## Compiler à partir du code source

Si vous préférez, vous pouvez compiler l’application vous-même. Quelques commandes suffisent.

### Installer les prérequis

Il vous faut [Git](https://git-scm.com) pour récupérer le code source et [mise](https://mise.jdx.dev), qui installe la bonne version de Rust et lance la compilation pour vous. Ajoutez ensuite ce dont votre système a besoin pour compiler une application de bureau :

- **Windows :** la chaîne d’outils MSVC, issue des Visual Studio Build Tools avec la charge de travail C++.
- **macOS :** les Xcode Command Line Tools. Lancez `xcode-select --install` dans un terminal.
- **Linux :** les bibliothèques de fenêtrage et graphiques. Sous Debian ou Ubuntu :

  ```sh
  sudo apt-get install libxkbcommon-dev libwayland-dev libx11-dev libxcursor-dev \
    libxrandr-dev libxi-dev libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev \
    libgl1-mesa-dev
  ```

  Les sessions X11 comme Wayland sont prises en charge.

### Compiler TruckPaint

1. Récupérez le code source :

   ```sh
   git clone https://github.com/acesyde/truckpaint.git
   cd truckpaint
   ```

2. Installez la chaîne d’outils fixée par le projet (Rust et ses outils) :

   ```sh
   mise install
   ```

3. Compilez l’application en mode release :

   ```sh
   mise run build
   ```

   La première compilation télécharge et compile toutes les dépendances : elle prend donc un moment. Les suivantes sont beaucoup plus rapides.

4. Lancez-la. L’exécutable s’appelle `truckpaint` (`truckpaint.exe` sous Windows), dans le dossier `target/release/` :

   ```sh
   ./target/release/truckpaint
   ```

Vous pouvez copier l’exécutable où vous voulez, ou lui créer un raccourci.

Pour mettre à jour une version compilée, lancez `git pull` dans le dossier du projet, puis à nouveau `mise install` et `mise run build`. Vos données sont conservées ici aussi.

## Si l’application ne démarre pas

TruckPaint dessine sa fenêtre avec Vulkan, DirectX 12 ou Metal. Avec d’anciens pilotes graphiques ou dans une machine virtuelle, il peut s’arrêter au lancement sur une erreur d’adaptateur graphique. Forcez un autre moteur graphique avec la variable `WGPU_BACKEND` :

```sh
WGPU_BACKEND=gl ./truckpaint      # OpenGL (Linux, Windows)
WGPU_BACKEND=vulkan ./truckpaint  # Vulkan
```

Sous Windows, dans PowerShell, définissez d’abord la variable : `$env:WGPU_BACKEND="gl"`, puis lancez `.\truckpaint.exe`. Si vous avez compilé à partir du code source, le programme se trouve dans le dossier `target/release/`.

Sous Windows et Linux, si la fenêtre ne peut pas être déplacée ou redimensionnée correctement, ouvrez <Ui id="home-preferences" /> et cochez <Ui id="prefs-system-title-bar" /> : la fenêtre utilise alors le cadre de votre système, avec les menus sur une ligne en dessous.

TruckPaint tient un journal de ce qu’il fait, dans le terminal et dans un fichier quotidien de son dossier de données (`logs/`). Joignez-le quand vous signalez un problème.
